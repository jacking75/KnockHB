# 실연결 시험 계획 (T13)

구현계획-1의 T14(두 PC 시험)·T15(성능 실측)를 실행하기 위한 계획서다. 이 계획은 사용자의 명시적 재개 지시가 있을 때만 실행한다. 지금 저장소가 있는 이 PC에서는 두 PC가 없으므로 실행하지 않는다.

## 이미 확인한 것 (실행함)

- 단위·계약 테스트: Host.Core 38, Go 전체, Viewer 58, PowerShell 계약 4. 모두 PASS(커밋 `ec67c5f`).
- 인코더 장치 검증(이 PC, RTX 4060 / i7-12700KF, 합성 1080p): nvenc 81.4fps, mf 104.3fps, openh264 62.7fps PASS. qsv·amf는 장치 없음.
- **한 PC 루프백 통합 검사**(`scripts/loopback-check.ps1`, 실제 Go 터널링 서버 + 실제 `ScreenShareSession` + C# 가짜 Viewer, 입력은 기록만, 약 9초): 21/21 PASS.
  - 고정 지원 ID 방 열기, PIN 없는 참가, 승인 없는 전 권한 부여, STUN/TURN 없는 직접 P2P 연결(연결까지 607ms, data-ready까지 834ms).
  - 7개 기능 채널 개통, 입력이 Host 입력 경로에 도달, 관리자 요청이 승인 창 없이 응답(헬퍼 없으면 denied + 새 epoch), 재개 입력.
  - 실제 캡처 H.264 RTP 수신(nvenc, 약 202 packet/s, 253KB/s), 모니터 목록·전환(새 inputEpoch)·전환 뒤 입력, 원격 명령 왕복, 채팅.
  - Viewer 교체(새 Viewer busy, 기존 Viewer replaced), 지원자 이탈 시 세션 종료·눌린 키 없음, 같은 ID 재접속(599ms).

루프백 검사는 **입력을 주입하지 않고 기록만** 한다. 따라서 아래가 남는다: 실제 `SendInput` 주입과 화면 반영, UAC/보안 데스크톱 캡처·조작(서비스 설치·SYSTEM AdminHelper 필요), 서로 다른 GPU, 진짜 두 PC 사이 네트워크 지연·대역, 브라우저 Viewer의 입력·디코딩·파일 저장.

## 환경

- A `192.168.0.61`: 지원자 PC. Go 터널링 서버(`RA_MODE=lan` + 자체 서명 인증서) + 브라우저 Viewer.
- B `192.168.0.74`: 대상 Host PC. 개발 설치. SSH 사용자 `jacking75NoteBook`(등록된 호스트 키·기존 환경 설정 사용).
- 후보: 커밋 `ec67c5f`(또는 그 시점 이후 확정 커밋)의 `package-host-dev.ps1` 산출물. 설치 전 candidate.json hash를 A/B 양쪽에서 대조.

## 준비 (화면 점유 없음)

1. A에서 `python scripts/prepare-e2e-tls.py --directory <폴더> --ip 192.168.0.61` → `server-cert.pem`/`server-key.pem`/`lan-test.cer`.
2. A에서 터널링 서버 기동: `RA_MODE=lan`, `RA_LISTEN=0.0.0.0:25001`, `RA_TLS_CERT/KEY`, `RA_VIEWER_DIR=web/viewer`. `/healthz` 200 확인.
3. B용 후보 생성: `package-host-dev.ps1 -TunnelUri https://192.168.0.61:25001/ -TunnelCertificate <폴더>/lan-test.cer ...`.
4. B에 SSH로 후보 복사, `install-host-dev.ps1 -Action Validate`로 hash 확인.
5. A 브라우저가 자체 서명 인증서를 신뢰(또는 예외 허용)하도록 준비. 방화벽 UDP 27002~27099 확인.
6. B 화면을 볼 수 있는 물리적 수단과, 막힐 때 세션을 끝낼 물리 키보드 조작(대상자 즉시 종료 또는 전원)을 준비.

## 실행 묶음 (각 묶음 전 사용자에게 목적·예상 점유 시간·중단 조건을 알린다)

### F1 — 연결·화면·입력 (목표 5분)

1. B: `install-host-dev.ps1 -Action Install` 후 `RemoteAssist.Update.exe` 관리자 실행. Tray에 지원 ID 표시 확인.
2. A: 브라우저로 `https://192.168.0.61:25001/` 열고 지원 ID 입력.
3. 판정: A에 B 화면이 뜬다(videoWidth>0). 마우스 이동·클릭·키 입력이 B에 **실제로 반영**된다(메모장 등에 글자 입력 확인). 지원자 이름이 B Tray에 표시된다.
4. 증거: A의 `#stats`(해상도·fps·경로), B 메모장 스크린샷, B `service-status.ndjson`.
- PASS/FAIL: 화면 표시 + 실제 입력 반영이면 PASS. 첫 실패에서 중단.

### F2 — 관리자/UAC (목표 5분, 현장 복귀 담당 필요)

1. 연결 상태에서 A가 B에서 UAC가 뜨는 동작을 한다(예: 설정 변경). 관리자 모드가 자동 진입돼 UAC 화면이 A에 보이고 A의 클릭·키가 UAC 창에 들어가는지 확인.
2. Ctrl+Alt+Del 버튼으로 SAS 전송 확인.
3. 판정: UAC·보안 데스크톱이 A에 보이고 조작된다(GPU가 다른 두 PC로 실측). 실패 시 폴백(일반 모드 유지·마지막 화면)만 확인하고 결함 기록.
- 첫 실패에서 중단하고 B를 현장에서 정리.

### F3 — 재접속·종료 (목표 3분)

1. A 브라우저 새로고침 → 자동 재접속 확인.
2. B 서비스 재시작(SSH) → 같은 지원 ID로 재접속 확인(허가 유지).
3. B에서 즉시 종료 → 세션 종료·허가 소멸, A는 재접속 안 됨 확인. 다시 관리자 실행하면 재개.

### F4 — 성능 실측 (T15, 화면 점유 최소)

1. 1080p 전체 화면에서 60초 평균 수신 fps(브라우저 `getStats` inbound-rtp framesPerSecond)와 수신 kbps.
2. 입력-표시 지연 p95: 알려진 입력(예: 큰 커서/글자)과 화면 반영 시점을 타임라인으로 측정.
3. 기준은 [제품 계약](../docs/product-contract.md) 시험 기준(1080p 평균 30fps 이상, 입력-표시 p95 150ms 이하). 미달이면 결함으로 기록하고 기준을 낮추지 않는다.

## 중단·정리

- 실패·신호 누락·시간 초과 시 즉시 중단. A 브라우저 탭 닫기, B에서 Tray 즉시 종료 → `install-host-dev.ps1 -Action Remove`. A 터널링 서버 종료.
- 화면을 점유한 채 코드 수정·환경 탐색·시나리오 추가를 하지 않는다. 원인과 준비가 바뀌지 않은 같은 시험을 반복하지 않는다.
- 실제 점유 시간·확인한 결과·새 결함을 실측값으로 working_log.md와 구현계획-1에 기록한다.
