# T14 나머지 기능 + T15 성능 실측 계획

[구현계획-1](구현계획-1.md) T14 중 아직 하지 않은 기능과 T15 성능을 두 PC에서 확인한다. 환경은 이전 시험과 같다(A `192.168.0.61` RTX 4060, B `192.168.0.74` Intel UHD + GTX 1660 Ti, 단일 모니터 1920×1080).

## 시험 전 변경 (아직 실연결 미검증)

- Viewer가 Host에 보내는 answer 사본에 H264 수신 level 4.2를 적는다([protocol.md](../docs/protocol.md) "H.264 수신 level"). 이전에는 Chrome answer의 3.1 때문에 1280×720으로 상한이 걸렸다. 그래서 1080p 기준을 잴 수 없었다.
- 측정 대상 창 `scripts/e2e-motion-target.ps1`(latency·motion 모드). B 사용자 세션에서 SSH 작업 스케줄러로 띄운다.

## 순서와 판정

준비는 `e2e-prepare.ps1 -Install -StartTunnel -PasswordEnv`, 지원 시작은 관리자 권한 사용자 작업으로 한다(이전과 같다).

1. 연결: 상단에 `1920×1080 · 디코딩 … fps`가 표시되면 PASS다. 720이면 level 변경이 반영되지 않은 것이므로 중단한다.
2. 원격 명령: `관리자(SYSTEM) 권한으로 실행`을 켜고 끈 상태로 각각 `whoami`를 실행한다. 결과가 `nt authority\system`과 B 사용자이면 PASS다.
3. Runbook: "네트워크 어댑터 개수 조회"를 실행해 결과가 표시되면 PASS다.
4. 클립보드: A→B로 `clip-a2b-<임의값>`을 전송한다. B에서 SSH로 사용자 클립보드를 읽어 같으면 PASS다. B→A는 SSH로 B 클립보드에 `clip-b2a-<임의값>`을 넣고 Viewer의 "대상 PC에서 읽기" 결과가 같으면 PASS다.
5. 채팅: Viewer에서 메시지를 보낸다. B Tray 채팅창에 보이면 PASS다(A 화면 영상으로 확인).
6. 파일 A→B: 1MiB 임의 파일을 보낸다. B `Downloads\RemoteAssist`에 같은 SHA256 파일이 있으면 PASS다.
7. 모니터 전환: B가 단일 모니터라 전환 시험은 할 수 없다. 목록이 1개로 정확히 나오는지만 본다.
8. T15 FPS: motion 창을 띄우고 60초 동안 `requestVideoFrameCallback` 표시 프레임과 `getVideoPlaybackQuality`를 잰다. 1920×1080에서 평균 30fps 이상이면 PASS다.
9. T15 입력-표시 지연: latency 창을 영상에서 클릭해 포커스를 준다. Viewer에서 키 이벤트를 40회 보내며, 보낸 시각부터 창 영역 밝기가 바뀐 프레임의 `expectedDisplayTime`까지를 잰다. p95 150ms 이하이면 PASS다. Viewer 입력 처리, 전송, Host 주입, 화면 갱신, 캡처, 인코딩, 전송, 디코딩, 표시를 모두 포함한다.

## 중단·정리

- 중단 조건: 판정 FAIL, 신호 누락, 10초 무응답. 즉시 탭을 닫고 B 대상 창을 닫은 뒤 원인을 분석한다.
- 점유 시간: 단계 1~9 약 6분. 단계 8은 60초 동안 화면을 건드리지 않는다.
- 정리: Viewer 탭 닫기 → B 대상 창 종료·제거 스크립트 → A 터널링 서버 종료·TLS 키 삭제. 받은 시험 파일은 B Downloads에서 지운다.
