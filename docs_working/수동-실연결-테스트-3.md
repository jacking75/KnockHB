# 사람이 직접 하는 두 PC 실연결 테스트 (수동)

사람이 두 PC 앞에서 직접 조작하며 몇 가지 동작으로 핵심 기능을 확인하는 절차다. 자동 하네스가 아니라 **손으로** 한다. [실연결-시험-계획-2](실연결-시험-계획-2.md)의 F1~F4를 사람이 따라 할 수 있게 순서대로 풀어 쓴 것이다.

- **A = 지원자 PC** (`192.168.0.61`): 시그널링 서버 + 브라우저 Viewer. 여기 앉아서 조작한다.
- **B = 대상 PC** (`192.168.0.74`): 지원받는 PC. 화면을 볼 수 있어야 하고, 막히면 끌 물리 키보드/전원이 있어야 한다.
- 두 PC 모두 소유한 테스트 PC여야 한다. 실제 업무 PC로 하지 않는다.
- 각 단계는 **기대 결과**를 적었다. 기대와 다르면 거기서 멈추고 §9 정리부터 한다. 원인이 바뀌지 않았으면 같은 단계를 반복하지 않는다.

> 참고: 코드·단위 테스트·한 PC 루프백 통합 검사(21/21 PASS)는 이미 끝냈다. 이 문서는 그걸로는 확인할 수 없는 것 — 실제 화면 표시, 실제 마우스/키보드 반영, UAC 화면 조작, 두 PC 사이 성능 — 만 사람이 눈으로 확인한다.
>
> **이 절차와 보조 스크립트는 A 머신에서 실행한다.** 이 저장소가 있는 머신이 A(B와 같은 LAN, B에 SSH 닿음)가 아니면, 저장소를 A 머신으로 옮겨 거기서 한다.

## 함께 시작하는 방법 (역할 분담)

이 테스트는 **A 머신에서 Claude Code를 실행**하면서 한다. 저(Claude)와 당신이 역할을 나눈다.

- **Claude(A에서)**: preflight·prepare 스크립트 실행, 시그널링 기동, B에 SSH 설치/재시작/로그 확인, 브라우저 Viewer로 접속·화면 확인·클릭·타이핑, 각 동작의 OK/실패 판정.
- **당신**: ① A 머신에서 이 저장소를 열고 Claude Code 세션 시작, ② **B에서 지원 프로그램 관리자 실행 + UAC 승인**(물리 조작), ③ 막히면 B에서 종료(즉시 종료 버튼/Ctrl+Alt+Shift+F10/전원).

진행 순서와 제가 알려주는 시점:
1. 당신이 A 머신에서 세션을 열고 "시작해"라고 한다.
2. 제가 `e2e-preflight.ps1`을 돌려 READY를 확인한다(FAIL이면 무엇을 고칠지 알려준다).
3. 제가 `e2e-prepare.ps1 -Install -StartSignaling`로 인증서·후보·B 설치·시그널링까지 준비한다.
4. **제가 "지금 B에서 RemoteAssist.Update.exe를 관리자 실행하고 UAC를 승인해 주세요"라고 알려준다. 당신이 B에서 그 조작을 한다.** (B Tray에 지원 ID가 뜨면 알려준다.)
5. 제가 브라우저로 지원 ID 접속 → 동작 1~5(화면·입력·UAC 클릭·재접속·대상자 종료)를 진행하고, 각 단계 결과를 당신에게 보고한다. 동작 3(UAC)처럼 당신 눈으로 같이 확인할 대목은 제가 스크린샷/상황을 알려주고 함께 판단한다.
6. 끝나면 제가 정리(§9)까지 하고 결과를 `working_log.md`에 기록한다.

아래 1장~10장은 위 순서를 손으로 할 때의 상세·기대 결과다. 스크립트로 준비했으면 4장(브라우저 접속)으로 바로 간다.

## 빠른 준비 (A 머신에서 스크립트로, 화면 점유 없음)

1장~3장을 손으로 하기 전에, A 머신에서 아래 두 스크립트로 준비 상태 점검과 준비 자동화를 할 수 있다.

```powershell
cd <저장소>
# 1. 준비 상태 점검 (읽기 전용: 도구·A IP·B SSH·포트 확인)
pwsh scripts\e2e-preflight.ps1          # READY 가 나와야 다음으로
# 2. 준비 자동화 (TLS 인증서 + Host 후보 빌드 + B에 SSH 설치 + 시그널링 기동)
pwsh scripts\e2e-prepare.ps1 -Install -StartSignaling
```

- `e2e-prepare.ps1 -Install`은 B에 **관리자 권한 SSH 세션**으로 설치한다(B의 OpenSSH 기본 셸·권한 설정 필요). SSH 설치가 막히면 `-Install` 없이 후보만 만들고, 아래 3장을 손으로 한다.
- B 주소/계정 기본값은 `192.168.0.74` / `jacking75NoteBook`이며 `-TargetHost`/`-TargetUser`로 바꾼다. A IP는 자동 감지하며 `-HostIp`로 지정할 수 있다.
- 스크립트로 준비했으면 4장(브라우저 접속)으로 바로 간다. 손으로 할 때는 1장부터 본다.

- [ ] A와 B가 같은 네트워크에 있고 서로 ping이 된다.
- [ ] A에 .NET 10 SDK, Go, Python(`cryptography` 설치), 최신 Chrome/Edge가 있다.
- [ ] B는 테스트용 PC이고, B 화면을 직접 볼 수 있다(모니터 또는 옆자리).
- [ ] B에서 지원을 끊을 방법을 안다: Tray **즉시 종료** 버튼 또는 **Ctrl+Alt+Shift+F10**, 최후엔 전원.
- [ ] 후보는 현재 커밋(`main`)으로 빌드한다.

## 1. A: 시그널링 서버 켜기 (화면 점유 없음)

A에서 PowerShell을 연다.

```powershell
cd C:\github_dev\KnockHB
# 1-1. A의 IP(192.168.0.61)용 자체 서명 TLS 인증서 만들기
python scripts\prepare-e2e-tls.py --directory .artifacts\tls --ip 192.168.0.61
# 1-2. 시그널링 서버 켜기 (이 창은 그대로 둔다)
$env:RA_MODE='lan'; $env:RA_LISTEN='0.0.0.0:25001'
$env:RA_TLS_CERT='.artifacts\tls\server-cert.pem'; $env:RA_TLS_KEY='.artifacts\tls\server-key.pem'
$env:RA_VIEWER_DIR='web\viewer'
cd server\signaling; go run .
```

**기대 결과:** 창에 `시그널링 시작 ... tls=true`가 뜬다.

확인: 다른 창에서 `curl.exe -k https://192.168.0.61:25001/healthz` → `ok`.

## 2. A: Host 설치 후보 만들기 (화면 점유 없음)

A에서 새 PowerShell 창.

```powershell
cd C:\github_dev\KnockHB
pwsh scripts\package-host-dev.ps1 `
  -SignalingUri https://192.168.0.61:25001/ `
  -SignalingCertificate .artifacts\tls\lan-test.cer `
```

**기대 결과:** `개발 후보 생성: ...\host-candidate`. 그 안에 `candidate.json`과 `payload\`가 있다.

이 폴더를 B로 복사한다(공유 폴더나 `scp`). B의 예: `C:\ra-candidate\`.

## 3. B: 설치하고 지원 시작 (여기서부터 B 화면을 본다)

설치 스크립트 `scripts\install-host-dev.ps1`도 B에 있어야 한다. B에 저장소를 체크아웃해 두거나, 그 스크립트 하나를 후보와 함께 복사한다(예: `C:\ra-candidate\install-host-dev.ps1`).

B에서 **관리자 권한** PowerShell.

```powershell
cd C:\ra-candidate          # install-host-dev.ps1 가 있는 위치
# 3-1. 후보 검증 (hash 확인만, 설치 안 함)
pwsh .\install-host-dev.ps1 -Action Validate -Package C:\ra-candidate
# 3-2. 설치
pwsh .\install-host-dev.ps1 -Action Install -Package C:\ra-candidate
```

**기대 결과:** `개발 설치 완료: C:\Program Files\RemoteAssist-Dev ...`.

이제 B에서 지원을 시작한다(일반 사용자로 로그인한 상태에서).

```powershell
& "C:\Program Files\RemoteAssist-Dev\RemoteAssist.Update.exe"
```

**기대 결과:** UAC 창이 뜬다 → 승인. 잠시 뒤 B 화면에 **RemoteAssist** 창이 뜨고 **지원 ID 9자리**(예: `418-207-935`)가 보인다. 안내문에 "지원자가 이 지원 ID로 접속한다"가 보인다.

> 여기서 B 사람은 더 할 일이 없다. 지원 ID만 A 사람에게 알려준다.

## 4. 동작 1 — 연결과 화면 보기 (A에서 조작)

A의 브라우저에서 `https://192.168.0.61:25001/` 를 연다.

- [ ] 처음엔 자체 서명 인증서 경고가 뜬다 → "고급 → 계속 진행"으로 예외를 허용한다(테스트용).
- [ ] 지원자 이름(예: `관리자`)과 B가 알려준 **지원 ID**를 입력하고 **접속**을 누른다.

**기대 결과:**
- A 화면에 **B의 바탕화면이 그대로 보인다**.
- 상단에 해상도·fps·`경로: <IP>:<포트>`가 표시된다(직접 P2P).
- B의 RemoteAssist 창에 테두리가 빨갛게 바뀌고 "원격 지원 중"과 지원자 이름이 보인다.

## 5. 동작 2 — 마우스·키보드가 실제로 B에 들어가는지

B에 미리 **메모장**을 하나 열어 둔다(B 사람이 열어도 되고, 아래에서 A가 열어도 된다).

A에서 B 화면(브라우저 안 영상)을 보며:

- [ ] 영상 안에서 **메모장을 클릭**한다.
- [ ] 키보드로 `remote test 1234` 를 친다.
- [ ] 한글도 확인: `원격 테스트` 를 친다(IME 확정 글자).
- [ ] 마우스로 메모장 창을 **드래그해서 옮긴다**.

**기대 결과:** B의 메모장에 `remote test 1234 원격 테스트`가 실제로 입력되고, 창이 움직인다. (A 사람과 B 사람이 같은 화면을 보며 "들어갔다"를 눈으로 확인)

---

## 6. 동작 3 — 관리자/UAC 화면 조작 (현장 복귀 담당 필요)

> B 옆에 사람이 있거나 B를 바로 조작할 수 있어야 한다. UAC가 막히면 A에서 못 풀 수 있으니 B에서 끌 준비를 한다.

A에서 B 화면을 보며:

- [ ] B에서 UAC가 뜨는 동작을 A가 원격으로 시작한다. 쉬운 방법: 영상 안에서 **시작 → `cmd` 입력 → `Ctrl+Shift+Enter`**(관리자 명령 프롬프트), 또는 아무 설치 프로그램 실행.

**기대 결과:**
- UAC 동의 화면(어두워진 보안 데스크톱)이 **A에도 보인다**.
- A에서 **예**를 클릭하면 눌린다.
- 상단/상태에 "관리자 모드"가 표시된다.

- [ ] (선택) 상단 **Ctrl+Alt+Del** 버튼을 누른다 → B에 보안 화면이 뜨는지 확인.

**이 동작이 핵심 검증이다.** GPU가 다른 두 PC에서 보안 데스크톱 캡처가 실제로 되는지를 여기서 처음으로 확인한다. 안 보이거나 조작이 안 되면 결함으로 기록하고(어떤 GPU·드라이버인지 함께), B에서 UAC를 직접 닫은 뒤 멈춘다.

## 7. 동작 4 — 끊김과 재접속

- [ ] A 브라우저에서 **새로고침(F5)**.

**기대 결과:** 잠깐 "다시 접속한다"가 보이고 몇 초 안에 화면이 다시 뜬다. B는 아무 조작도 하지 않는다.

- [ ] (선택) B에서 서비스 재시작: 관리자 PowerShell에서 `Restart-Service RemoteAssistHost`.

**기대 결과:** 서비스가 올라오면 **같은 지원 ID**로 A가 자동 재접속된다(허가가 유지되므로 B에서 다시 실행할 필요 없음).

---

## 8. 동작 5 — 대상자가 지원 끊기 (허가 폐기 확인)

B에서:

- [ ] RemoteAssist 창의 **즉시 종료** 버튼을 누른다(또는 **Ctrl+Alt+Shift+F10**).

**기대 결과:**
- A의 화면 공유가 끊긴다.
- A가 다시 접속을 시도해도 **연결되지 않는다**("대상 PC가 아직 지원 대기 중이 아니다").
- B 창에 "관리자 권한으로 실행하면 지원을 시작한다"가 뜬다.

- [ ] B에서 다시 `RemoteAssist.Update.exe`를 관리자 실행 → A가 다시 접속되면 재개가 정상.

---

## 9. 정리 (끝났거나 중간에 멈췄을 때)

- [ ] A: 브라우저 탭을 닫는다.
- [ ] B: Tray **즉시 종료**로 세션을 끝낸다.
- [ ] B: 제거 — 관리자 PowerShell에서 `cd C:\ra-candidate; pwsh .\install-host-dev.ps1 -Action Remove` (서비스·설치 폴더·지원 허가 정리, 받은 파일과 감사 기록은 남음).
- [ ] A: 시그널링 서버 창에서 `Ctrl+C`.
- [ ] A: `.artifacts\tls`의 인증서·키를 테스트가 끝나면 지운다.

---

## 10. (선택) 동작 6 — 성능 눈대중

연결된 상태에서 A 브라우저 상단 `#stats`의 fps·kbps를 1분간 본다. 1080p 전체화면에서 평균 **30fps 이상**이면 기준 충족. 입력-표시 지연은 메모장에 빠르게 타이핑했을 때 체감 지연으로 대략 본다(정밀 측정은 별도). 수치는 추정하지 말고 본 값을 그대로 기록한다.

## 결과 기록

끝나면 아래를 `working_log.md`에 적는다.

- 실제 화면 점유 시간(동작 1~5).
- 각 동작의 OK/실패와, 실패면 증상·B의 GPU/드라이버.
- 특히 **동작 2(실제 입력 반영)**, **동작 3(UAC 화면)**, **동작 4(재접속)** 결과.

동작 3에서 UAC 캡처/조작이 실패하면 그것만 결함으로 남기고, 나머지(화면·입력·재접속)가 되면 "관리자 모드 외 기능은 동작, UAC 캡처는 GPU X에서 미확인"으로 구분해 적는다.
