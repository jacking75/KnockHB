# C01–C16 실행 관측 계약

실제 E2E는 이번 구현 요청에서 실행하지 않는다. 다음 실행용 후보를 만들 때 다음 관측 코드를 함께 빌드한다.

- DesktopTestDriver API 1이 조작을 소유한다. 별도 `scripts/e2e-desktop/` 도구는 UIA 토글·OS 상태를 읽고, C11의 비공개 OLE 보관·복원과 C16의 소유 서비스 1회 장애를 수행한다. UIA Invoke로 제품 동의를 대신하지 않는다.
- 브라우저 관측은 실제 WebSocket·RTCPeerConnection·DataChannel·파일 저장 API의 호출을 전달하며 메타데이터만 기록한다. 채널 메시지나 파일 핸들을 만들어 제품에 주입하지 않는다.
- 제품의 개발 설치 `dev-owner.json`이 가리키는 현재 회차에만 `CaseTrace`를 활성화한다. 보호 회차 폴더 아래 미리 만든 trace 디렉터리에 프로세스별 QPC·실제 수명·입력 예약 ACK·native 전이·생산자 종료·복구 up·캡처 시작을 기록한다. 설치 소유자가 없으면 파일을 만들지 않는다. 제품 동의·권한·IPC 판단에는 영향을 주지 않는다.
- trace에는 코드/PIN, 토큰, 비밀번호, 입력 텍스트, 원래 클립보드, 파일 내용, Runbook 출력이 들어가지 않는다. 관측 실패·초과·누락은 수용 실패이며, 기록이 없다는 이유로 동작 횟수 0을 가정하지 않는다.
- C16의 500ms·3s, HostStop의 1s, reset·clipboard·dismiss의 제한은 같은 머신·같은 QPC 또는 브라우저 clock의 사건 차이로 판정한다. CLI/SSH 수집 기동 시간과 기능 지연을 혼합하지 않는다. 모든 호출은 별도로 단계 deadline과 900초 전역 상한을 따른다.
- C11은 모든 열거된 OLE 형식의 소유 복제에 성공한 뒤에만 변경을 허용한다. 복제할 수 없는 저장 매체·target-device 형식·64MiB 초과 원본은 변경 전에 차단한다. 원본은 STA 도구의 메모리에만 존재하며 원문·길이·형식 목록·해시를 증거로 내보내지 않는다. 복원은 실제 OleSetClipboard/OleFlushClipboard 완료를 요구한다.

이 문서는 제품 권한 모델을 변경하지 않는 개발 관측 계약이다. 정식 설치 경로에는 개발 소유자 파일과 trace 디렉터리를 배포하지 않는다.
