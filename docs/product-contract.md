# 1차 제품 계약과 수용 기준

2026-10-08 E01 결정이다. 구현 현황은 루트 구현계획에서만 관리한다.

2026-10-22 변경: [최초 관리자 실행](startup-preparation.md)에서 한 세션 전체 권한을 부여하는 경로를 추가한다. 이 경로는 현재 콘솔 사용자·세션에 묶인 보호된 일회성 허가와 코드/PIN 인증을 결합하며, 추가 로컬 동의 창 없이 최초 피어에게 권한을 부여한다. 본문의 별도 동의·건별 승인 기준은 이 허가가 없는 기존 수동 경로에 적용한다. 종료·만료·사용자 변경 시 권한 폐기, 상태 표시, 즉시 종료, 감사는 양쪽 경로에 공통이다.

2026-10-23 사용자 결정(최신, 위 모든 승인·인증 서술에 우선): 지원자 PC와 대상 PC는 서로 신뢰하는 관계다. 대상자가 프로그램을 관리자 권한으로 한 번 실행하면 이후 대상자의 추가 조작 없이 지원자가 모든 기능(화면·입력·관리자/UAC·파일·클립보드·Runbook·모니터 전환)을 쓴다. PIN·일회성 코드·본인 확인 절차는 없고, 대상 PC는 고정 지원 ID로 접속을 기다린다. 지원자가 끊어도 허가는 유지돼 같은 ID로 즉시 재접속한다. 허가는 서비스 메모리에만 있고 대상자의 즉시 종료·Tray 종료·서비스 중지·사용자 변경 때 폐기한다. 재부팅 뒤에는 대상자가 다시 관리자로 실행한다.

## 지원 범위와 위협 경계

2026-10-23 제품 규격: NAT 환경에서 직접 P2P 연결 성공은 제품의 필수 요구사항이다. 특정 E2E의 가정이나 연결 가능한 환경만 고르는 조건이 아니다. P2P 연결 실패를 정상 제약으로 인정하거나 TURN 릴레이·릴레이 폴백으로 대체하지 않는다. STUN/ICE를 이용한 직접 연결은 유지한다. 실제 연결 오류는 요구사항 미충족으로 기록하고 원인을 조사·수정한다. 연결 오류·타임아웃 때 입력 해제와 세션 정리는 유지한다.

Windows 10 22H2/Windows 11 x64의 단일 로그인 콘솔 사용자를 1차 대상으로 한다. RDP·사용자 전환 중에는 승인과 세션을 폐기하며 다른 사용자의 화면을 승계하지 않는다. Viewer는 최신 안정 Chrome/Edge 데스크톱을 대상으로 한다. GPU는 허용 H.264 인코더의 실제 초기화·출력·브라우저 디코딩이 검증된 조합만 지원한다. HW가 없는 환경은 libopenh264를 시험하며 등록 여부를 지원 성공으로 세지 않는다.

Host당 승인된 지원 세션은 하나다. 최소 신원 방식은 코드/PIN을 별도 경로로 전달하고 통화 등으로 지원자를 확인하는 pairing identity다. 지원자의 입력 이름은 항상 '자기 신고, 별도 확인 필요'로 표시한다. 서버 재시작·피어 이탈·시그널링 상실·대상 사용자 변경은 세션을 종료한다.

로컬 악성 관리자 또는 대상 사용자 세션을 완전히 장악한 악성코드로부터 신뢰 UI를 보장하지 않는다. 원격 Viewer·다른 로컬 사용자·재생 명령·지연 callback·위조 권한은 방어 대상이다. 서비스의 SYSTEM 권한은 일반 헬퍼에 범용 실행 권한을 부여하지 않는다.

## 상태 전이

| 상태 | 허용 전이 | 기능 실행 |
|---|---|---|
| 생성 | pairing, 종료 | 없음 |
| pairing | 동의 대기, 종료 | 없음 |
| 동의 대기 | 협상, 종료 | 없음 |
| 협상 | 활성, 종료 | 승인한 기능만 준비 |
| 활성 | 복구 대기, 종료 | 현재 권한·세대·lease를 실행 직전 검사 |
| 복구 대기 | 활성, 종료 | 새 입력·미디어 중단 |
| 종료 | 없음 | 승인 폐기, 큐 무효화, 키 해제 |

종료는 최종 상태다. 동일 코드로 새 피어가 기존 동의를 승계하지 않는다. ICE만 끊기고 인증된 시그널링/로컬 lease가 유지되는 경우에 한해 같은 피어의 복구를 허용한다. 복구는 새 transport generation으로 수행하며 관리자·건별 승인 중 단절은 전체 종료다. 복구 성공은 실제 V29/F07 증거로 판정한다.

## 권한

screen/control/admin/file/clipboard/diagnostics/runbook/chat은 독립 승인 항목이다. control에는 screen이 필요하며 admin 요청에는 control도 필요하다. admin은 관리자 요청을 허용할 범위이며 실제 진입에는 별도의 만료 있는 현장 승인이 필요하다. admin은 다른 기능을 자동 부여하지 않는다. 진단만 승인하면 화면과 입력은 0이다. chat 동의 없이 clipboard만 승인하면 같은 전송 채널을 사용해도 chat 메시지를 실행하지 않는다. 파일은 기능 승인 외에도 전송 건별 수락과 로컬 저장 위치 선택이 필요하다. Runbook은 고정 본문 hash와 인자에 대한 건별 승인이다. Viewer가 보낸 consent/granted로 Host 권한을 변경하지 않는다.

## 시험 정책

아래 값은 시험 전에 고정한 수용 기준이며 실측값이 아니다. 미달을 결과에 맞춰 낮추지 않는다.

| 항목 | 기준 | 검증 |
|---|---|---|
| 로컬 철회 후 새 송신·입력 | 1초 이내 차단 | E24/F04 |
| 관리 작업 전체 정리 | 5초 deadline, native hang은 헬퍼 감독 종료 | E09/E14/F09 |
| 지원 ID | Host 고정 9자리(ProgramData `device-id.txt`), PIN 없음. Host 연결 중 방 유지, Viewer 이탈마다 Host가 새 세션을 준비해 같은 ID로 재접속 | E18/F04 |
| 초기 join | 10초 | E08 |
| 협상 | 30초 | E09/E10 |
| 시그널링 heartbeat | 5초 간격, 15초 무응답 종료 | E08/F09 |
| ICE 복구 | 2초 단절 확인, 연속 최대3회·각30초 | E29/F07 |
| 1080p 인코딩 | 실제 출력 기준 30fps 이상 | E06/E11/F02 |
| 1080p LAN 송신·표시 | 30fps 목표, 60초 측정에서 평균 30fps 이상 | E13/F11 |
| LAN 입력-표시 | p95 150ms 이하, 별도 타임라인 실측 | E39/F11 |
| 로컬 서버 부하 | 100개 룸·200개 연결, 10분, 무한 큐/잔여 룸 0 | E38/E40 |
| 장시간·반복 | 2시간 활성, start/stop 100회, handle/heap 추이 기록 | E40/F11 |
| 메시지 | 시그널링 128KiB, 데이터 JSON 32KiB, ICE 큐 256개 | E04/E08 |

개발 정적 listener는 loopback TCP 25001로 한정한다. 운영은 직접 TLS HTTPS/WSS로 하고 인증서 검사 우회를 제공하지 않는다. coturn 후보 포트는 TCP 25002/25003(UDP listen 없음) 및 relay UDP 27100~27199다. 브라우저의 동적 WebRTC 소스 포트는 앱에서 고정할 수 없으므로 수신 서비스 listener/relay 포트 정책과 구분한다. 엄격한 전체 소스 포트 고정이 필요한 조직에는 별도 방화벽 정책이 필요하며 E29/F07에서 실제 도달성을 검증한다.

정식 코드 서명 인증서·TLS 시그널링 서버·두 물리 PC·현장 승인자는 외부 준비물이다. TURN 서버는 제품 준비물이 아니다. 개발 인증서나 단일 PC 시험을 정식 배포/Gate B로 바꾸지 않는다. CI는 사용자가 별도로 요청할 때만 다룬다.
