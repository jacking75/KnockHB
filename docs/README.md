# RemoteAssist 개발자 문서

RemoteAssist는 대상자의 동의를 받아 Windows PC를 진단하고 조작하기 위한 원격 지원 도구다. 저장소 이름은 `KnockHB`, 코드의 제품명과 네임스페이스는 `RemoteAssist`다.

**현재 실행 경로는 HostRun 콘솔에서 명시적으로 화면 보기를 승인하는 개발 경로다.** 시그널링 v1·일회성 참가·오류/종료·인코더/캡처 기반을 보완했다. 원격 입력·서비스와 Tray의 인증 IPC·관리자·보조 기능·설치/업데이트는 아직 미구현이다. TURN credential 발급과 설정 전달은 존재하지만 실제 allocation·갱신·복구는 검증하지 않았다.

2026-10-08 구현 기준이다. 현재 실측·차단 환경은 [실행 증거](../docs_working/implementation-evidence-2026-10-08.md), 지원 기준은 [제품 계약](product-contract.md), 진행 상태는 루트 구현계획에서 확인한다.

## 앱을 이해하는 데 필요한 다섯 가지

1. **Host는 대상 PC다.** 지원자의 화면을 보내는 것이 아니라 도움을 받는 사람의 모니터를 캡처한다.
2. **Viewer는 지원자의 브라우저다.** 별도 네이티브 Viewer 설치 없이 `<video>`에서 화면을 받는다.
3. **시그널링 서버는 만남과 연결 협상을 중개한다.** 현재 Go 서버는 화면 프레임을 받거나 H.264를 디코딩하지 않는다.
4. **TURN 설정 전달과 실제 릴레이 성공은 다르다.** 인증된 joined에 단기 credential을 전달하며 실제 coturn·NAT·갱신 검증은 남아 있다.
5. **화면 보기 승인은 콘솔에서만 받는다.** 제품의 독립 권한 UI·상시 표시·관리자 승인·원클릭 종료는 Service/Tray 구현 뒤 검증해야 한다.

## 구현 상태 지도

`구현`은 코드가 존재한다는 뜻이며, 모든 환경의 검증을 마쳤다는 뜻이 아니다. `골격`은 프로젝트/기본 진입점만 존재한다. `설계`는 동작 코드를 아직 연결하지 않은 기능이다.

| 기능 | 상태 | 실제 동작 또는 남은 일 |
|---|---|---|
| 세션 코드·PIN·Host 토큰 발급 | 구현 | 메모리 룸, 기본 10분 참가 유효기간 |
| 역할별 참가·SDP/ICE 릴레이 | 구현 | Host/Viewer 슬롯 각 1개; 예약·ACK ready 원자화 |
| 모니터 캡처 | 구현 | WGC 우선, WGC 미지원 시 DXGI 선택 |
| H.264 인코딩 | 구현 | 후보별 실제 초기화·출력 폴백; 강제 후보는 엄격 검사 |
| 화면 송신·브라우저 표시 | 구현 | HostRun 기반; 원격 입력 없음 |
| 해상도·FPS·비트레이트 표시 | 구현 | 브라우저 통계·selected pair 양쪽 P2P/relay 확인 |
| Windows 서비스 | 골격 | 30초 주기의 대기 루프; 화면 공유와 미연결 |
| WPF 트레이 앱 | 골격 | 일반 권한의 빈 창; 실제 트레이·동의 UI 없음 |
| 입력 DTO | 일부 구현 | binding/세대/정규 좌표 파서; 데이터채널/SendInput 미구현 |
| 동의·권한 철회·감사 로그 | 일부 구현 | 콘솔 화면 승인·권한 폐기; 제품 UI·감사 저장 미구현 |
| TURN·ICE restart | 일부 구현 | credential·양쪽 설정 전달; allocation/갱신/복구 미검증 |
| 파일·채팅·클립보드·모니터 전환 | 설계 | 초기 모니터 선택과 세션 중 전환은 별개 |
| 관리자 모드·UAC·SAS | 설계 | 사용자 세션 헬퍼와 별도 승인 경계 필요 |
| 상태 대시보드·Runbook | 설계 | 1차 차별화 기능, 실행에는 사람의 승인 필요 |
| AI·RBAC·세션 이관·무인 접속 | 백로그 | 초기 릴리스 범위 아님 |

## 용어 사전

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| 세션 / 룸 | 사용자 관점의 지원 작업 / 서버 메모리에서 두 피어를 묶는 객체 |
| 세션 코드 | 사용자가 전달하는 9자리 숫자 문자열. 선행 0을 보존한다 |
| PIN | Viewer 참가 확인용 4자리 숫자 문자열. 사용자 간 별도 경로로 전달한다 |
| Host 토큰 | Host 슬롯 인증용 난수. Viewer에게 전달하지 않는다 |
| SDP | 미디어 종류·코덱·연결 정보를 기술하는 협상 문서. offer/answer에 담는다 |
| ICE candidate | 두 피어가 연결을 시도할 네트워크 주소 후보 |
| STUN / TURN | 외부 주소 탐색을 돕는 서버 / 직접 연결이 안 될 때 패킷을 전달하는 릴레이 |
| PeerConnection | WebRTC의 연결·협상·미디어 전송 객체 |
| WGC / DXGI | Windows Graphics Capture / Desktop Duplication 캡처 경로 |
| BGRA / stride | 픽셀의 바이트 순서 / 영상 한 줄의 바이트 간격 |
| staging texture | GPU 영상을 CPU가 읽도록 복사해 놓는 Direct3D 텍스처 |
| 키프레임 | 이전 프레임에 대한 의존도를 끊고 디코딩을 다시 시작할 수 있게 하는 프레임 |
| Session 0 | Windows 서비스가 실행되는 세션. 로그인 사용자의 화면 세션과 다르다 |
| Named Pipe | 같은 PC의 서비스·사용자 프로세스 간 통신에 사용할 예정인 IPC |
| DoD | 태스크의 완료 조건. 코드 작성 완료와 실제 검증 완료를 구분하는 기준 |

## 문서의 기준과 갱신 규칙

`docs/`는 지속적으로 유지하는 기준 문서의 위치다. 개발 중 임시로 만드는 리뷰·조사·분석·작업 메모·태스크 리스크 문서는 루트의 `docs_working/`에 작성한다. 루트의 구현계획은 기존 위치를 유지한다.

| 정보 | 기준 문서/파일 |
|---|---|
| 제품 구조·현재 동작·목표 구조 | [아키텍처](architecture.md), [기술 사양](technical-specification.md) |
| JSON 필드·메시지 의미 | [protocol.md](protocol.md) 하나가 기준 |
| 패키지 고정값 | [Directory.Packages.props](../Directory.Packages.props), [go.mod](../server/signaling/go.mod) |
| 태스크·완료 상태 | [통합 구현계획](../원격제어-구현계획.md): E01~E41 구현·F01~F12 최종 E2E. 기존 T는 대응표, 과거 PoC는 이력으로 관리 |
| 발견된 결함·회귀 조건 | [리뷰·태스크 리스크](../docs_working/code-review-task-risks-2026-10-07.md) |

설계나 프로토콜을 바꾸면 먼저 해당 기준 문서를 갱신하고 코드를 맞춘다. 기존 문서의 목표 설명과 실제 코드가 다르면 조용히 완료 처리하지 말고 구현 상태와 차이를 적는다. 특히 이 문서군의 **현재 구현**, **목표 설계**, **미확정** 표시는 유지한다.

다이어그램은 저장소에서 직접 관리하는 Mermaid 코드 블록이다. GitHub 등 Mermaid 지원 Markdown 뷰어에서 렌더링할 수 있으며, 지원하지 않는 뷰어에서도 인접한 설명과 표로 흐름을 읽을 수 있다.
