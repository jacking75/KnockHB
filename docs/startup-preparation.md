# 최초 관리자 실행과 연결 준비

2026-10-22 사용자 결정: 신뢰된 지원 PC와 대상 PC의 지원 작업에 필요한 OS 권한 준비는 대상 프로그램의 최초 관리자 실행에 모은다. 사용자가 최초 Windows UAC를 승인한 뒤 서비스 설치, 보호 경로/권한, 관리자 헬퍼, 네트워크 허용을 준비한다. 알려진 준비 누락을 원격 조작 도중 다시 묻지 않는다.

## 실행 순서

1. 사용자가 설치/시작 프로그램을 실행하고 Windows UAC를 직접 승인한다. 설치 프로세스의 관리자 토큰으로 하위 설치·설정 프로그램을 실행한다. 추가 `runas`를 호출하지 않는다.
2. 검증된 파일을 보호 설치 경로에 배치하고 SYSTEM 서비스를 등록한다.
3. 화면·입력·관리자·입력 복원 헬퍼 파일과 보호 권한을 확인한다.
4. 실제 네트워크 소유 프로세스인 `RemoteAssist.Host.Helper.exe`의 WebRTC UDP `27002~27099`와 HTTPS/TURN 연결에 필요한 방화벽 규칙을 등록한다. 서비스의 감사/제어 HTTPS 송신도 준비한다. 실행 파일 경로와 포트에 한정하며 방화벽 전체나 UAC를 끄지 않는다.
5. 등록된 규칙을 다시 읽어 일치 여부, 현재 프로필의 전체 수신 차단·그룹 정책 제한·대상 실행 파일 차단 규칙을 확인한다. 준비 실패면 서비스를 시작하지 않는다.
6. 서비스는 시작 시 설정을 새로 변경하지 않고 준비 상태를 검증한다. 현재 콘솔 세션의 사용자 토큰과 SYSTEM 헬퍼 생성에 필요한 권한을 확인한 뒤 준비 신호와 Tray를 제공한다. 검증 실패면 지원 코드 생성·접속을 허용하지 않는다.

방화벽 규칙은 설치 버전의 경로에 묶인다. 업데이트도 새 버전 규칙을 서비스 기동 전에 준비하고, 실패 시 새 규칙을 정리한다. 기존 버전 규칙은 rollback을 위해 보존하며 제거 시 버전별 소유 규칙을 삭제한다. 다른 프로그램이나 정책의 규칙은 변경하지 않는다.

## UX 목표와 구현 범위

최초 대화형 관리자 실행을 한 번의 지원 세션 권한 부여로 삼는다. 런처는 보호된 일회성 시작 허가를 현재 Windows 사용자 SID·콘솔 세션에 묶어 기록한다. 서비스는 10분 이내의 허가를 한 번만 소비해 지원 코드를 만들고, 코드/PIN으로 인증한 첫 지원 연결에 화면·제어·관리자·파일·클립보드·진단·등록 Runbook·채팅 권한을 부여한다. 접속자 표시 이름을 신원 증거로 사용하지 않는다. 코드/PIN을 받은 상대가 신뢰한 지원자라는 기존 전달 모델을 유지한다.

허가는 최대 2시간이며 종료·사용자 변경·서비스 재시작 뒤 재사용하지 않는다. 소비 시 최초 실행 프로세스의 PID·시작 시각·Windows 세션이 여전히 일치해야 하므로 런처 종료나 재부팅 뒤 남은 파일은 권한으로 사용할 수 없다. 재부팅·예약 업데이트·복구 작업은 새로운 허가를 만들지 않는다. 대상자는 연결 상태를 볼 수 있고 언제든 즉시 종료한다. 이 경로에서는 관리자 모드·모니터 전환·등록 Runbook마다 대상자에게 다시 승인받지 않는다. 파일 수신은 사용자 Downloads의 RemoteAssist 폴더에 저장하며 기존 파일을 덮어쓰지 않는다. 송신 파일 선택은 파일을 고르는 동작으로 남으며 원격 제어로 수행할 수 있다.

허가 없는 기존 설치의 서비스 기동은 기존 수동 지원 흐름을 유지한다. 최초 실행 UX의 구현과 실제 원격 수용 검증은 구별한다.

현재 관리자 모드에서는 공유 모니터를 고정한다. 관리자 헬퍼의 캡처·입력과 입력 복구 감독이 처음 승인된 모니터·세대에 묶여 있으므로 모니터 전환을 허용하지 않는다. 관리자 모드와 병행하는 파일·등록 Runbook은 추가 승인 창 없이 실행한다. 다른 모니터로 관리자 조작을 이어가는 기능에는 관리자 헬퍼의 모니터 재바인딩 구현이 필요하다.

OS 준비와 제품의 세션 권한 부여는 구별한다. 다른 앱에서 발생하는 UAC는 최초 실행으로 일괄 승인할 수 없으므로 준비된 관리자 화면 경로에서 지원자가 조작해야 한다.

최초 지원의 관리자 화면은 세션 허가 만료와 독립 입력 lease를 따른다. 기존 수동 경로의 보안 데스크톱 30초 제한을 최초 지원에 적용하지 않는다. 일반 데스크톱은 기존 WGC 우선·DXGI 폴백 캡처를 사용하고 보안 데스크톱은 DXGI 경로를 사용한다. 보안 데스크톱의 GPU별 캡처 가능 여부는 실제 수용에서 확인해야 한다.

## 검증

### SAS 사전 준비

Ctrl+Alt+Delete 전송에 필요한 `SoftwareSASGeneration`도 최초 설치에서 준비한다. 값이 없으면 서비스 허용(1), 접근성 앱만 허용(2)이면 기존 기능을 보존한 양쪽 허용(3)으로 설정한다. 명시적 금지(0)나 알 수 없는 형식/값은 준비 실패로 처리한다. 이미 1/3이면 변경하지 않는다. 원래 값과 형식은 보호된 `ProgramData/RemoteAssist/startup-sas.json`에 먼저 기록한다. 실패 시 pending 변경만 복구하며, 버전 업데이트 뒤에도 committed 소유 기록을 유지한다. 제거할 때 현재 값이 우리가 설정한 값일 때만 원래 상태로 복구하고 외부 변경은 덮어쓰지 않는다. 서비스는 설정을 변경하지 않고 검증만 한다. 이는 컴퓨터 전체의 서비스 SAS 정책이며 UAC 또는 보안 데스크톱을 끄는 설정이 아니다. [Microsoft 정책 설명](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-winlogon#softwaresasgeneration)

코드 검증에서는 준비 계획, 규칙 범위, 기존 규칙 충돌, 부분 실패 rollback, 누락/변조 시 준비 거부를 입력 없는 테스트로 확인한다. 실제 서비스·방화벽·UAC 변경과 원격 E2E는 사용자의 테스트 재개 지시 전까지 실행하지 않는다.

실제 수용은 초기 UAC 승인 후 방화벽 추가 팝업 없이 연결되는지, 관리자/보안 화면 조작과 일반 화면 복귀가 되는지 별도로 확인해야 한다. 준비 검사 성공은 기능 PASS가 아니다.
